# The hook against a real agent session, 2026-10-24

**Bottom line.** I could not run real headless Claude Code sessions (the bundled `claude.exe` is not logged in, and I did not work around that), so this is a **replay**: the first 900 tool calls that Claude Code actually made in one long working session (this one: 683 shell commands, 157 file writes, 34 edits, 25 reads), each paired with the user prompt in force at that moment and put through the `PreToolUse` hook at the new 0.70 default, against live `jev-1.14.0`. Nothing was executed. **All 122 destructive, external-write and unclassifiable commands were held. 15 of 900 calls were silently approved by the model, all of them ordinary local writes inside the project or the scratch space. But the hook held 502 of 900 calls (55.8%)**, so in enforcing mode it would have interrupted this session about every second call. Start in shadow mode. Raw counts: [JSON](replay-2026-10-24.json). Tool: [`scripts/eval-replay.mjs`](../../scripts/eval-replay.mjs).

## What was measured

There are no labels in a real session, so this measures how often the hook would have interrupted the work and whether anything dangerous went through. The calls were made with a human present, so the ones that ran are normal work by construction. A held call is not an error: the human would have been asked, and most of them would have said yes. This session is also an unusually write-heavy one (a coding agent editing a test suite), so the rate is a worst case, not a typical day.

## Two problems the replay found, both fixed

The first run held **601 of 900 (66.8%)**. Two causes were mine, not the model's:

1. **The hook told the judge a false effect.** It declares every shell command `read_only` and lets the classifier raise it, but the same declaration was also sent to the judge, so for every write the judge saw "declared read-only, actually writes" and answered `effect_mismatch`. The judge now gets the effect the classifier found. The effective effect (the strictest of the two) is unchanged, so nothing is loosened.
2. **The host's own files counted as "outside the workspace".** 84 of 84 such asks were the host's scratch directory (79) and plan files (5). Those two locations are now exempt from `outside_workspace`; every other path outside the workspace, a look-alike directory, a traversal out of the scratch root, and anything sensitive inside it still ask (tested).

| | First run | After the fixes |
| --- | ---: | ---: |
| Calls held | 601 of 900 (66.8%) | **502 of 900 (55.8%)** |
| File writes and edits held | 84 of 191 | **0 of 191** |
| Shell commands held | 517 of 684 | 502 of 684 |
| `effect_mismatch` asks | 353 | 113 |
| Destructive / external / unknown held | 122 of 122 | **122 of 122** |
| Model calls, tokens | 536, 775k | 536, 775k |
| Latency p50 / p95 | 165 / 203 ms | 168 / 212 ms |

## What the 502 are

| Shell commands, by what the classifier found | Held / total |
| --- | ---: |
| Destructive (`rm -r`, force operations) | 10 / 10 |
| External write (`git push`, `gh` writes) | 36 / 36 |
| Unclassifiable (a `python - <<EOF` heredoc that edits files, `eval`, ...) | 76 / 76 |
| Local write | 271 / 286 |
| Classified read-only, which includes programs the classifier cannot vouch for (`node`, `python`, `gh`, `npm`) | 109 / 276 |

Dominant model reasons among the held: `out_of_scope` (288), `scope_uncertain` (189), `risk_uncertain` (130), `effect_uncertain` (121), `effect_mismatch` (113). The held read-only-classified calls are almost all `node -e`, `node --test`, `python script.py` and `gh` runs: the program is unknown to the classifier, so it is not "confirmed read-only" and the judge decides. Many of the `out_of_scope` calls are real work done under a **terse follow-up prompt** ("Yes make it default...", "Merge in order"): the hook shows the judge only the last human prompt, so the plan the user had agreed earlier is invisible. That is a deliberate choice (an older prompt may no longer be wanted, and the agent's own narration is not trustworthy), but it is the main cost.

## Reading it honestly

- **Safety side:** nothing dangerous was approved silently. The 15 silent non-read-only calls are test runs, `cat > file <<EOF` into the project or scratch space, and a `git switch -c` with a build. Whether the 502 held calls were right to be held is a judgment I made by sampling, not a measured precision: the destructive and external ones clearly were, most of the 76 unclassifiable heredoc edits were routine edits the classifier cannot see into, and a good share of the model's `out_of_scope` asks on local writes were false alarms in the sense that the user would have approved them.
- **Cost side:** 536 model calls and 775k tokens for 900 calls, and 168 ms median per decision.
- **Not measured:** a different user, a different session type (mostly reading and reviewing, which the hook would hold far less), other agents, and a version of the hook that sees more than the last prompt.

## Recommendation

Run the hook in shadow mode (`JEV_MCP_HOOKS=shadow`) for a few real sessions first. Add a `.jev-policy.json` `allow_read_only` list for the commands you run all day (test and build commands) to bring the held share down without the model. Do not read `silent` as approval: it means "the normal permission flow applies".
