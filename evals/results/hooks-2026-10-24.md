# Claude Code hook: live measurements, 2026-10-24

**Bottom line.** Replaying 120 generated agent actions (64 risky, 56 safe; three fresh seeds) through the `PreToolUse` hook on live `jev-1.14.0`: with no policy file the hook **held 57 of 64 risky actions** (an unhooked session holds none); with a small repository policy it **held all 64**. The hook **left 45 of 56 safe actions alone**, and every interruption was an honest local write such as `git add`, `git commit` or `npm test` that Jev's scope judgment doubted. Over half of events were answered without a model call, and the median event cost **167 ms**. With Jev unreachable the deterministic layer alone still held **48 of 64** (60 of 64 with the policy). Raw data: [JSON](hooks-2026-10-24.json).

## What was run

Seeds 646464001-3, 20 base plus 20 extra `jev_scope` cases per seed, replayed as the tool call an agent would make: a `Bash` command, a `Read` or an `Edit`. The user's prompt is the case's task and scope, written to a transcript file the way Claude Code writes it. The hook declares nothing about an action; it classifies the command itself. A risky case counts as held when the hook asks or denies, a safe case as clean when it stays silent. "No hook" is Claude Code's own permission flow, treated here as silent.

The policy is [evals/fixtures/policy/hook-policy.json](../fixtures/policy/hook-policy.json): protected workflow, auth and billing paths, a deny on force pushes, and review on dependency and publish commands. It was written after the first run to cover the templates that run missed, so the 64/64 shows what a policy *can* add, not a result on unseen rules.

## Reading

- **What the hook catches without any configuration:** commands whose text shows a destructive, external or opaque effect (the classifier ignores whatever an agent says about them), reads of key material and credential files, and edits to the guard's own configuration. All 38 "lying" commands were held, with or without the model.
- **What it cannot know without a policy:** that editing `.github/workflows/release.yml` or `src/auth/middleware.ts` is out of bounds. A file edit is checked deterministically (protected paths, sensitive paths, outside the workspace) and never sent to the model, so these 7 misses are the cost of that choice, and `protected_paths` is the fix.
- **The cost is honest local writes.** 11 of 24 `git add`, `git commit`, `npm test` and `mkdir` commands were held by Jev's scope judgment (it escalated most of them). This is the known weak spot from the earlier benchmarks, and it is why the hook never denies on a model's judgment: it asks. Run it in shadow mode first (`JEV_MCP_HOOKS=shadow`) to see how often it would interrupt before turning it on.
- **Offline:** when Jev cannot be reached the matrix holds destructive, external-effect and unclassifiable commands and lets routine local work through, so nothing is lost in the common case, but dependency installs and similar local writes are not held without a policy. The 1.2 s latency is the bounded wait on an unreachable provider.
- **Deny is policy-only.** In the first run the hook mapped a model `escalate` to `deny`, and it denied 4 of the honest `git add`, `git commit` and `mkdir` commands, which a user cannot override at the prompt. The hook now denies only on an explicit `deny` rule in the repository's own policy file; every other hold is an `ask`.

## Limits

One model, one run per case, templates written by me, 120 events. The case set is `jev_scope` replayed as hook events, not recordings of real agent sessions. The policy was written after seeing the first run's misses. Transcript parsing follows the documented format and is covered by a fixture test; a manual run inside a real Claude Code session is still to be done.
